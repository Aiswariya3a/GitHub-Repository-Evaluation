# Milestone v2.0: Frontend Dashboard

**Status:** ✅ SHIPPED 2026-07-13
**Phase:** 5
**Total Plans:** 4

## Overview

Frontend dashboard enhancements for the multi-agent SLM evaluation pipeline: fixed PDF report generation, added ingestion snapshot and evaluation detail tabs, implemented plagiarism detection display, extracted inline JavaScript to dedicated files, enhanced analytics with score distribution and session comparison, organized CSS, and improved UX with error handling, skeleton loading, and styled flash messages.

## Phases

### Phase 5: Frontend Dashboard

**Goal:** Enhance the web dashboard to surface all pipeline data (ingestion snapshots, evaluation details, plagiarism, analytics) with organized, maintainable frontend code.

**Depends on:** Phase 1-4 (v1.0 backend pipeline)

**Plans:** 4 plans

Plans:

- [x] 05-01: Fix PDF report generation pipeline
- [x] 05-02: Ingestion snapshot + evaluation detail tabs
- [x] 05-03: Plagiarism results + JS extraction + analytics enhancement
- [x] 05-04: CSS organization + UX polish

**Details:**

Phase 5 transformed the frontend from a basic dashboard into a feature-rich UI that surfaces all evaluation pipeline data. Key deliverables:
- PDF generation refactored from subprocess-based CLI to callable module with lazy import (circular dependency fix)
- Three new tab renderers: Ingestion (file tree with LOC), Evaluation Detail (per-criterion cards with scores/confidence/evidence), Collaboration (contributors, timeline, KPIs)
- Plagiarism similarity table with low-confidence filter chip
- Score distribution histogram and session comparison table on analytics page
- All inline JavaScript extracted to 5 `.js` files with shared utilities in `common.js` via `window.*` namespace
- CSS organized into 14 section headers across two files, deduplicated
- Error handling: API error divs, `.catch()` handlers, skeleton loading states
- Flash messages upgraded to styled containers

## Milestone Summary

**Key Decisions:**

- Decision: Lazy import of `generate_pdf` inside `report_service.generate()` to break circular dependency (Rationale: `pdf_gen -> services -> pdf_gen` cycle)
- Decision: `session_context()` returns 4-tuple `(session, rows, summary, plagiarism)` (Rationale: Plagiarism data needed without breaking existing callers)
- Decision: Shared JS utilities on `window.*` namespace in common.js (Rationale: Cross-file access without a bundler)
- Decision: 3 separate `DOMContentLoaded` handlers in dashboard.js (Rationale: One file serves dashboard, overview, and analytics pages)
- Decision: CSS section headers with consistent naming (`BASE`, `LAYOUT`, `COMPONENTS`, `STATES`, `RESPONSIVE`) (Rationale: Maintainability without a CSS preprocessor)

**Issues Resolved:**

- Circular import between `pdf_gen.py` and services package — fixed with lazy import pattern
- `container.evaluations.get_evaluation_result()` did not exist — fixed by using `container.repositories.evaluations.get_evaluation_result()`

**Issues Deferred:**

- Command palette JS remains inline in `base.html` (low priority for extraction)
- No formal phase VERIFICATION.md files created

**Technical Debt Incurred:**

- Integration tests require external services (Ollama + PostgreSQL) — not run during milestone
